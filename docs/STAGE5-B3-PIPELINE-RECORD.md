## 1. The five-state durability model

The gameplay-facing durability states are distinct and never interchangeable (§3.2 of the v1.8 architecture):

| State | What holds it | Claims |
|---|---|---|
| `ConfirmedCanonical` (T3) | The verified canonical chain (Batch 2 CAS) | Canonical commitment — the sole authority (§9) |
| `T1Pending` | The durable T1 journal (§3) | Durable, replayable intent — **never** canonical, **never** suppressing |
| `InMemoryPending` | Process memory only (`CommitPipeline::stage`) | Nothing — dies with the process (P0-5) |
| `ProvisionalEncounter` | The encounter transaction's provisional lane | Rollback-able; governed by the class-aware rollback rules (§8) |
| `ReconstructibleRoutine` | The Stage 4 reconstruction machinery (B4 integration) | Never manufactures rewards — labels only |

The binding invariants, each pinned by tests: no in-memory event claims durability (`crash_before_t1_staging_dies_with_the_process` — staged keys are honestly unknown to a fresh process); no journaled event claims T3 without verified chain inclusion (`t1_pending_until_genuine_t3`; the journal never returns `ConfirmedT3` — that state is pipeline-owned); no provisional silently becomes durable (promotion is explicit and idempotent; `EncounterProvisional` effects apply at recovery only through an actionable committed transaction — the journal's durable commit is the evidence of the encounter's acceptance); the routine lane never manufactures rewards (steps and routine counters are structurally absent from the envelope schema — §7); failed commits leave truthful pending/unknown (`AmbiguousCommit` reconciled by reread+verify, never guessed; the medium-failure and Unknown paths retain the attempt exactly); confirmed is never silently rolled back (the durable lane never rolls back — §8).

## 2. Per-key status lattice and transitions

`CommitPipeline` tracks every consequential identity through four phases (`KeyStatus{phase, transaction}`):

```
InMemory ──capture()──▶ JournaledT1 ──commit_canonical()──▶ InConfirmedChain
   │ (stage, no I/O)        │                                  ▲
   │                        └──mark_applied()──▶ AppliedToLivePending
   │                                                  (live application reported;
   ▼ drop = honest loss (P0-5)                        confirmed separately)
discard_staged() → gone (in-memory only, never journal/chain state)
```

- `stage(ConsequenceEnvelope)` — no I/O; byte-identical restage is a no-op; conflicting reuse of a tracked identity fails closed (`ConflictingReuse` — a durable identity is never reissued to a different envelope).
- `capture(position, classification, dependencies, frontier, plan)` — journals the staged set as ONE T1 transaction; the receipt returns only after the fsync (§4); an `AmbiguousCommit` is reconciled immediately via the journal's `reconcile_write` (reread+verify — `Committed` without a fabricated acknowledgment, or `NotCommitted` retry-safe with the staged set retained).
- `mark_applied(&[ConsequenceId])` — the application reports live application; applying an unjournaled key is refused (`AppliedBeforeJournal` — durable-before-discard).
- `open(medium, journal)` seeds per-key tracking from the journal's committed transactions (T1 is durable across sessions — a reopened pipeline reports `JournaledT1` truthfully) and then the session-open chain walk collects every chain-confirmed key (O(chain) at open, O(new revisions) per commit — never per tick; the B2 trusted-cursor model).
- `status(id)` is truthful in every state; `is_confirmed(id)` consults the verified chain walk only; `confirmed_coverage(id)` returns the per-key coverage evidence (§9).

## 3. The journal format and durability contract

One append-only file per campaign (`journal/1` header + `journal-record/1` length-framed records), exclusively flock-locked for the instance lifetime (process death releases; a same-process second open blocks — tests drop before reopening; `scan_file` is the lock-free read, absent file = empty journal). Every record carries the SHA-256 of the previous record's bytes, header-anchored — tamper evidence for commit and cancellation records that no capture digest covers. The chain re-anchors at validated commits/cancellations so damage before a later validating commit is contained and reported.

**The four durability states** (`TransactionDurability`, the reviewer's binding distinction): `Readable` (frames decode but no commit record — inert), `Committed` (the commit record is present, complete, digest-verified, and durably synced), `AcknowledgedT1` (**session-scoped, never persisted** — a reloaded journal or a reconciliation never claims a historical acknowledgment; `acknowledged_this_session` is the only source), `ConfirmedT3` (pipeline-owned; the journal never returns it). `transaction_status(TransactionId)` + `identity_status(ConsequenceId)` expose the per-transaction and per-key views; `is_actionable = committed && !canceled`.

**Torn-tail and corruption rules (the module docs are the contract of record):** the writer never appends past an unresolved tail (open-for-write truncates to the last valid commit/cancellation boundary, the observed tail reported); torn/zero-filled/undecodable trailing data after the last valid commit is the **inert W1 tail** (reported, truncated on open, never replayed); a **decodable** commit or cancellation failing semantic checks is post-write corruption of committed history under the single-writer discipline → **fail closed (`CorruptCommitted{at, rule}`), evidence preserved byte-for-byte, never reinterpreted as an inert tail**. No truncation ever removes an acknowledged transaction.

**One fsync per completed transaction** — at the commit record, through a WRITE-access handle (the B2 Windows `FlushFileBuffers` lesson carried into B3; `sync_count()` exposes the evidence: N transactions ⇒ N syncs, never per-capture).

## 4. Transaction framing and integrity

A transaction frame = one capture record per envelope (embedding the envelope's canonical bytes as a bounded length-prefixed blob — `envelope/1` objects are self-describing, domain-tagged) + an explicit **transaction-commit record** carrying: the `TransactionId`, the journal sequence (**strictly +1 across commits AND cancellations** — a gap or regression is corruption), the capture record count, the SHA-256 digest over the full capture record set, the identity set (validated equal to the envelopes' ids), the source position, the durability classification, the dependencies, the frontier entries, and the complete plan blob (B4's prepared-transition integration). **Actionable iff the commit record is present, complete, verified, and durably acknowledged at the declared tier.**

`TransactionId` (`transaction-id/1`) = SHA-256 over (identities + classification + plan) — **retry-stable** (excludes position/tick/spans/deltas): a genuinely retried operation re-derives the identical transaction; a duplicate append is recognized idempotently (the existing receipt returns — no second frame, no second fsync). A new operation with a different plan or identity set is a fresh transaction.

The fault seam: `JournalFaultPoint{BeforeCaptures, MidCaptureWrite, CapturesWritten, CommitWritten, AfterSync} × FaultAction{Abort, InjectError}` via `T1Journal::open_with(path, faults)` — the journal's own seam mirroring B2's, driving §14.

## 5. ConsequenceId — the structured consequential identity

`consequence-id/1`: domain-tagged, schema `u8`, region `u32`, episode `u64`, npc `u32` — fixed widths on the wire (B1 primitives; no `usize`). Strict fail-closed decode (domain/version/widths/trailing); canonical `Ord` by (region, episode, npc) for canonical key-set ordering; `canonical_bytes` is the stable idempotency-key material (the identity never changes across retries — the architecture's requirement A).

**The packed Stage 4 key conversion (§5.5):** both directions against the ACTUAL engine-slice layout, read firsthand from `consequence_key` (`region.rs:183`): `(region << 54) | (episode << 10) | npc` — npc bits 0–9, episode bits 10–53, region bits 54–63; a bijection between the bounded domain and the full `u64` range (the all-bounds identity (1023, 2^44−1, 1023) packs to `u64::MAX`). `pack_stage4` enforces **strict bounds — rejection, never wrap** (`PackedKeyError::{NpcOverflow, EpisodeOverflow, RegionOverflow}`): the unchecked legacy expression would alias npc 1024 onto (episode 1, npc 0) — an identity collision never packed. `unpack_stage4` is total (every `u64` decodes). Three boundary tests: exact-literal layout pins plus the mirrored legacy expression (engine-persist cannot depend on engine-slice — the dependency direction), full-layout round-trips in both directions at every field boundary, and the npc-1024≡episode-1 aliasing regression one-past each boundary and at full widths. **The legacy implementation and its `capture-ledger/2` fingerprint domain are untouched**; the in-memory ledger's migration to structured keys is deferred with a stated trigger (P1-7, B4).

## 6. The monotonic episode frontier

`reconstruct_episode_frontier(region, anchor, journal, confirmed) -> u64`: the next fresh episode = 1 + the maximum across (a) the journal's committed envelope identities for the region (**canceled transactions included — a durably issued identity is never reused**), (b) the commit records' carried frontier entries, (c) the chain-confirmed identities, and (d) the anchor's snapshot identities — never the latest snapshot alone; overflow fails closed. No identity previously issued into durable state is ever reused; retries retain their original idempotency identity (the `TransactionId` stability, §4); genuinely new operations receive fresh identities (tests: the frontier advances beyond every durably issued episode; untouched regions start at 1).

## 7. The consequential-state envelope

`envelope/1` — the complete consequential-state record a durable transaction journals (§5.4.1's minimum sufficient envelope): `ConsequenceEnvelope { id, sub_spans, delta, expected_prior, baseline, position, dependencies }`.

- **Class-homogeneous sub-spans** (`ClassifiedSpan { span, class }`): one `DurabilityClass` per sub-span — a mixed aggregate is a **partition**, never one class for the whole (the reviewer's coverage-refinement requirement). Sorted, disjoint (a shared occurrence is a per-occurrence conflict, fail closed); same-class adjacency non-canonical (it would have composed); **different-class adjacency is the legitimate partition boundary**; gaps within one envelope are legitimate holes (a hole is a rolled-back occurrence this capture does not cover).
- **`CounterDelta`** over exactly the four enumerated authoritative counters (`milestones` u64; `pending_signals`/`captured`/`credits` i64) — **steps and routine counters are structurally absent, never envelope-restorable**. `apply_to` is pure and checked: the whole delta or none, overflow fails closed. i64 rides the wire as two's-complement LE u64 bit patterns.
- **The uniform per-occurrence unit** (+1 milestone, +1 signal into ONE lane, +1 coverage-insert per crossing) is a **validated invariant**: a span-bearing delta must be exactly unit × occurrence-count, the movement in a single lane, net lane movement == milestones — only then is partial-replay scaling exact. Span-less envelopes are net-zero lane movements (an activation `{captured: −S, credits: +S}`), applied whole-or-not by identity.
- **`SourceBaseline { counters, award: AwardCheckpoint }`** — the verified source baseline observed at preparation: the durable lane is the (anchor, journal) reconciliation base; the full checkpoint is the encounter-rollback material. **`expected_prior` is required causality data, contractually distinct from the baseline** (they coincide in the clean single-event case).
- **`missing_against(&Coverage) → PartialApplication`** — the exact partial replay: per-class missing sub-spans via `Coverage::missing_of` against the anchor's **durable** lane, with per-class uniform-unit-scaled deltas; `EncounterProvisional` missing effects are routed to the encounter machinery, never silently promoted.
- Bounded decode: counts also bounded by remaining input (17 bytes per sub-span, 16 per dependency); `MAX_ENVELOPE_SUB_SPANS`/`MAX_ENVELOPE_DEPENDENCIES` = 2^16; dependencies strictly ascending + dedup; baseline cross-lane overlap rejected.

## 8. Occurrence spans and the class-aware rollback semantics

`OccurrenceSpan` is the ratified `(lo, hi]` — exclusive lower, inclusive upper (`covers(k)` = `lo < k <= hi`; lo = the last already-covered occurrence per §5.4.1). `Coverage` is a sorted, maximally-composed, disjoint span list where **holes are legitimate** (a hole is a rolled-back provisional occurrence): `insert_span` is a **set operation** (union — composes touching spans, preserves gaps), `remove_span` subtracts and splits, `missing_of` is exact against hole-bearing anchors (an anchor covering {4,6} against the span (3,7] yields exactly {5,7}). Wire: `award-state/1`, bounded by `MAX_COVERAGE_SPANS = 2^16`; decode rejects inverted/unsorted/adjacent/overlapping non-canonical forms.

`AwardState { durable: Coverage, provisional: Coverage }` — the two-lane representation that replaced the failed scalar design (the reviewer's counterexample: an encounter retaining durable occurrence 4 while rolling back provisional 5, then gaining durable 6 — a scalar watermark of 6 would falsely cover the hole at 5, permanently losing the rolled-back award; the impossibility argument for the scalar does not hold because the v1.8 rollback table itself contemplates per-classification retention within one encounter):

- `award_durable(k)`/`award_provisional(k)` — idempotent set-inserts of `(k−1, k]`; occurrence 0 never; an already-covered occurrence is a no-op (one occurrence never counts as two awards); re-recording under the other class is a no-op (the class change is the promotion).
- `promote_provisional(span)` — explicit, idempotent.
- **`rollback(checkpoint)` restores `checkpoint.provisional` MINUS the current durable coverage** — the rollback-coherence rule (`c68061f`): durable promotions survive the failure per their classification and are **never reintroduced** into the provisional lane (one occurrence, two lanes = an incoherent state); discarded provisional occurrences become legitimately earnable again; legitimate rollback holes are preserved (no blanket contiguity invariant on award states).
- `commit_encounter()` folds the provisional lane into durable.
- `validate`/decode **reject cross-lane overlap** — never silently repaired.

## 9. Applied-key authority — the four-tier suppression

**Only the confirmed canonical chain establishes canonical commitment.** The separately persisted applied-marker of v1.7 is **removed by design** (an in-memory mutation plus an independent journal fsync are not one durable transaction; a marker recorded after a live application but before the containing snapshot publishes would claim representation the loaded durable state lacks — the review's W4 counterexample). The four tiers:

| Tier | What it is | Suppression authority |
|---|---|---|
| Chain-confirmed identity | A key in the canonical chain's committed set (the verified walk) | **Always** — the whole envelope is committed |
| Journal intent | The durable envelope (T1) with its covered span | **Never** — an intent may require replay |
| Snapshot-represented coverage | The occurrence coverage materialized in the loaded verified anchor (the durable lane) | **For the covered occurrences** |
| In-run replay dedup | The spans applied during the current recovery operation | Within one recovery run only |

Canonical confirmation (the rule, never relaxed): (1) the revision carrying the batch is included in the **verified chain** — re-read and hash-verified through the medium's read paths (the session-open walk or the post-append read-back), never a bare `Accepted`; (2) the `consequence-batch/1` content object is read back **by its content identity** and **every `ConsequenceId` is individually validated** — present, with exactly the attempted occurrence coverage and producing transaction, no unattempted keys, placed by the walk at the confirming revision (a mismatch is `ConfirmationInvalid`, never a false T3); (3) the `ConfirmationReceipt` carries the exact revision, epoch, every validated key, the **actual** durability tier, and the authority mode **from the founding record** (labeled `T3-local (standalone)`; no silent mode conversions). The batch's wire form: `consequence-batch/1`, `BatchEntry { id, transaction, coverage }` strictly ascending and unique, referenced via the revision's `content_refs`; **the revision's idempotency key IS the batch content hash** (chain-unique, medium-enforced — rebases and idempotent retries can never double-install). Canceled transactions are excluded; chain-confirmed keys are never re-batched.

## 10. Trusted-snapshot coverage vs journal intent

Reconciliation is a **deterministic pure function of (anchor, journal, confirmed)**: load the latest verified anchor's coverage; walk the journal in sequence order; for each valid envelope apply exactly the occurrences covered by neither the chain-committed keys (tier 1) nor the anchor's coverage (tier 3) — `(max(lo, A), hi]` per span, exact against hole-bearing anchors. A crash at any point mid-reconciliation restarts from the same base and re-derives the same result — **no durable intermediate ever claims representation** (the W4 window); the result becomes durable in ONE atomic operation, the caller's next snapshot/revision publication (the B2 nine-step append). Holes never suppress journal intents; the four tiers stay distinct (tests: chain suppression vs journal presence; the older-anchor re-apply; the in-run dedup across overlapping envelopes).

## 11. The EncounterJournal boundary (policy-free)

`EncounterJournal::new(SignalLane)` fixes the encounter's uniform unit lane; `begin_participant(id, AwardState, CounterValues)` checkpoints both award lanes and the counters (an incoherent cross-lane begin fails closed); `record_effect(id, occurrence, class)` applies the uniform unit under the **application-supplied** classification as an idempotent set-insert; `promote(id, occurrence)` is the explicit idempotent durable promotion; `rollback()` implements §8's coherence rule with the counters restoring to checkpoint + the units of occurrences newly durable **whose units this encounter recorded** (a pre-existing provisional occurrence promoted mid-encounter keeps its checkpoint counters — never double-counted); `commit(pipeline, position, dependencies, frontier, plan)` routes the eligible effects as the class-homogeneous sub-span partition (one envelope per participant — the durable/provisional lane differences since the checkpoint, separately tagged), staged + captured as ONE boundary transaction (tx classification `EncounterProvisional`), then folds the live state (`commit_encounter`). The canonical confirmation remains the pipeline's separate `commit_canonical` (the effects are honestly `JournaledT1` until then). A failed boundary **discards the uncaptured staging** (`pipeline.discard_staged` — in-memory pending only, never touching journaled or confirmed keys) and the retry re-derives identical envelopes (byte-identical restage = a pipeline no-op). Both terminals close the encounter (`EncounterClosed` on further operations; a re-attempt is a new journal — the same identity after a rollback, a new episode after a commit). **The engine never decides which consumables/equipment/proficiency/quest effects are durable — the application supplies every classification.**

## 12. Unknown reconciliation (on the B2 medium)

`commit_canonical` appends against the pipeline's verified head. `RejectedStaleParent` → the suffix re-walk determines the now-confirmed keys (a key confirmed by another writer's batch is confirmed, never re-submitted — the foreign path returns `Confirmed` without our revision), the remaining keys **rebase with identical per-key identities and coverages** on the observed parent, retried once; a second rejection retains the attempt. `Unknown` → the exact revision/record/key set is retained (a new attempt is refused — `AttemptUnresolved`); `reconcile_pending` → `Installed` still requires the full read-back walk + individual per-key validation, `NotInstalled` is retry-safe under the same content identity (the idempotency key = the batch content hash makes reinstallation impossible), `Unverifiable` stays pending; `retry_pending` re-walks then resubmits (the same record bytes when the parent matches, the rebase when it does not). Across a restart: a fresh pipeline's session-open walk resolves an installed-but-unacknowledged revision to `InConfirmedChain` by **verified chain inclusion** — never by the lost local receipt (`unknown_window_survives_restart_and_resolves_by_the_chain_walk`).

## 13. Recovery, cancellation, and supersession

`reconcile(anchor, journal, confirmed)` (§10's pure function): **Contract A** — for every actionable (committed AND uncanceled) transaction, each envelope's still-missing occurrences apply atomically and exactly-once by identity: the counters advance by the uniform unit × the missing count, the missing spans promote into the durable lane clearing the provisional lane (cross-lane coherence); a span-less movement applies whole-or-not **by identity only** (the chain tier is the only durable suppression authority — counter equality is never evidence; two journaled movements with identical deltas each apply exactly once); steps and transient gameplay history are structurally never fabricated. **Contract B** — the temporal discriminator first: anchor tick ≤ source tick ⇒ `BenignAbsence` (Contract A unconditional; the transition marked consequence-recovered, transition-not-reconstructed — B4 owns the reconstruction). At-or-after ⇒ the comparable-state check: **individual signal lanes are never compared** (captures transfer pending → captured and activations transfer captured → credits, so a causally valid anchor legitimately holds less of an individual lane — the `e007b2e` corrective): the witnesses are the milestone counter and the occurrence coverage; a coherent anchor holds exactly `baseline.milestones + newly_materialized` (the anchor's award lanes minus the envelope's baseline lanes, per-span, saturating) — fewer milestones than the coverage materializes or more than any lane explains both fail closed (`Incompatible`, evidence preserved). `TransitionClassification {BenignAbsence, PreState, PartialState, PostState, Incompatible{detail}}`. The conservation invariant is checked after every application (a violation fails closed). The canonical re-drive is the caller's separate act (`commit_canonical` under the original identities — never falsely confirmed).

**Supersession is only via an explicit durable `CancellationRecord`** — versioned, journal-ordered, reason-coded (`ApplicationPolicy`/`CausalSupersession`/`GovernedResolution`), validated before suppression (`UnknownTarget`/`AlreadyCanceled`, pre-write); a higher journal sequence **never** auto-discards (`is_actionable = committed && !canceled`); canceled transactions never promote at recovery; the frontier still counts their durably issued identities (§6).
